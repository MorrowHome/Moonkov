# 按屏幕组织游戏 UI

仅阅读目标屏幕对应部分。以下是决策依据，不要求一次任务实现全部功能。

## 战斗 HUD 与交互提示

将需要持续注意、临时查看和紧急处理的信息分层。保留中心视野与敌人轮廓；交互提示靠近玩家关注区域，但不要覆盖准星目标。任务描述、日志和完整属性尽量进入按需展开的界面。

健康、弹药、氧气、撤离时间等资源根据游戏风险确定优先级。数值变化应稳定、易比较；不要让数字抖动牵动整组布局。低资源同时提供明确状态文字或符号，不能只把细小数字改红。持续危险与瞬时受击的反馈应能区分，避免多个警告互相淹没。

查看实际场景中的显示效果。浅色地表、暗室、粒子和快速转动都可能暴露面板对比与遮挡问题；只选与当前改动有关的背景检查。

## 背包、仓库与装备

重复格子、边框、品质色和紧凑属性表是有效工具。先区分容器、装备槽、物品网格、当前选择与详情，不要为追求构图变化破坏规律。

- 格子包含本项目需要的图标、数量和状态；耐久、重量、品质等按实际规则显示，避免每格重复全部属性。
- 详情提供清楚名称、用途和可执行动作；比较同类装备时属性顺序、单位与正负方向一致。
- 若修改拖放或整理：处理合法目标、非法位置、容量不足、取消，以及失败后原物品位置。区分悬停物品、选中物品与正在拖动物品。
- 大量物品先保证滚动、筛选和选中反馈；不要仅为降低视觉密度隐藏必要信息，也不要无依据地重写虚拟化系统。

## 商店与交易

价格、持有货币、购买数量、库存与确认动作在同一决策范围内。无钱、缺货、容量不足或限制条件应说明原因。等待期间避免重复请求，成交后以真实返回更新货币和物品；失败后保持可重试状态。

继承当前经济和交易校验，不因 UI 改版修改价格、买卖规则或服务端权限。只做视觉原型时明确说明交易是模拟的。

## 主菜单、暂停与设置

主菜单用角色、场景或关键视觉传达游戏身份，并让继续/开始等主要入口容易找到。暂停菜单与当前操作上下文一致，不强迫玩家等待装饰动画。

设置按玩家理解的类别分组。修改相关控件时，确认即时生效或需要应用、保存或取消后的结果，以及键位冲突与不可用选项的说明。模态窗口打开时聚焦到有意义控件，关闭后恢复焦点；暂停不应被假设能停止联网世界。

## 结算与任务界面

先呈现这次成功、失败或撤离结果，再展开奖励、损失和明细。奖励动画不阻挡返回与继续，跳过后状态一致。奖励、持久化与联网结算使用现有结果，不通过动画播放完成来认定发放成功。

任务或地图界面突出当前目标、目的地与可行动项，区分已完成、追踪中和不可达状态。只显示项目实际提供的位置与进度，不能为设计效果伪造游戏状态。
