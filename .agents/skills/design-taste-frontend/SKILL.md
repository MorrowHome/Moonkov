# Game UI Design Taste

将游戏的世界观和操作需求转化为有辨识度、可读、可用的界面。沿用原 skill 的「从题材提炼设计语言、实际观看产物再修正」思路；原营销网页的构图规则和研究分数不作为游戏 UI 的验收标准。保留 `design-taste-frontend` 安装标识以兼容现有调用。

## 先确定这次交付

- 读取现有界面、截图、样式、输入与数据绑定，确认平台、目标分辨率、玩家此时在做什么，以及这次改动的边界。能从项目判断的事实直接确认；只有会改变方案且无法推断的信息才询问。
- 区分设计方案、可交互原型、项目内实现与视觉评审。用户要求项目内实现时，默认接入现有游戏界面；只有明确需要浏览器原型时才使用 HTML/CSS。
- 延续已有 UI 框架和美术语言。一次样式优化不应引入框架迁移、经济规则调整或新的网络状态来源。
- Unity 实现读取 [references/unity-game-ui.md](references/unity-game-ui.md)；具体页面的布局与交互读取 [references/game-screens.md](references/game-screens.md)。小改动只读取相关段落。

## 从游戏中提炼方向

从项目已有内容选择少量能解释视觉决策的线索：玩家身份、装备材质、世界中的设备、阵营符号、资源压力、叙事时代。形成一句可执行的方向，例如：「月面作业终端的设备分区用于组织补给，氧气与撤离风险保持最高可读性」。

把方向落实到界面表面、字形、边缘、图标、信息分区和反馈节奏。避免仅以「高级、科幻、现代」代替具体决定。已有方向清晰时直接沿用；需要重新定调时可比较少量合适方向，无需随机抽签或为了新鲜感重做整屏。

保留与任务有关的视觉丰富度：装备缩略图、角色立绘、场景背景、材质或阵营色。装饰强度由游戏需要决定，不设图片数量、动画数量或屏幕填满比例。战斗 HUD 留出的空间服务于观察与瞄准；背包的重复格子服务于检索，二者不按营销网页规则处理。

## 先组织玩家决策，再画界面

对目标屏幕说明三个问题：玩家必须立刻知道什么、接下来能做什么、失败或等待时如何理解状态。按当前情境组织层级：

- 战斗中的准星、受击、弹药与紧急资源强调快速识别，避免遮住威胁与瞄准区域。
- 管理界面的筛选、容量、价格、属性与比较支持扫描；主操作与选中物品靠近，减少来回寻找。
- 弹窗清楚表达操作后果、确认和取消；输入焦点与关闭后返回的位置保持可预测。

流程复杂且示意图有帮助时使用 Mermaid；简单调整无需额外流程文档。

## 建立适合游戏的视觉语言

- **层级与密度：** 为标题、分组、正文、数值和辅助说明定义稳定角色。大标题只用于需要它的界面，不能挤掉背包、设置与战斗信息。统一间距与对齐，先改善结构再加装饰。
- **色彩：** 区分背景层、正文、可交互、选中、危险、成功与物品品质。危险色不能同时只承担品牌强调。品质、可用性与警告不能只靠颜色传达，可结合图标、文字、形状或描边。
- **游戏允许的表现：** 分隔线、细边框、格子、等宽数字、渐变、发光和透明面板可以使用，但应有分组、材质或状态含义，并在实际背景上可读。避免无理由堆叠霓虹、模糊和细碎文字。
- **字体与中文：** 优先使用项目已有且许可适用的字体。检查中文、数字、标点和中英混排；不要把拉丁字距与大写标签规则机械套到中文。实际显示尺寸下可读比设计稿中的字号更重要。
- **图标与图片：** 沿用项目图标体系，统一轮廓、视觉重量与状态。重要物品提供图标和清楚名称；陌生符号提供必要说明。缺失素材明确标记，不能把占位素材宣称为完成。
- **动效与声音：** 反馈解释选中、确认、获得、失败或风险变化。日常操作不等待无意义的入场动画，紧急警告保持优先级。复用已有音效路由，并避免重复触发。对强闪烁、晃动与长动画提供适合项目的减弱方式。

## 让状态和输入完整

覆盖本次控件实际会出现的状态：默认、悬停、焦点、按下、选中、禁用、等待、空列表、失败与成功。不要为无关状态扩展系统，但不能只完成静态默认画面。

按已支持的输入验证使用路径。键鼠考虑快捷键提示、滚轮与拖放；手柄考虑焦点起点、移动、返回与滚动跟随；触屏考虑命中区与拖动冲突。没有项目依据时不擅自新增平台支持。

操作必须绑定真实行为。购买、丢弃、装备、应用设置等状态以现有系统结果为准；不要用视觉上成功的假回调替代实际事务。等待时阻止重复提交，失败时保留可理解的反馈和恢复路径。设计原型可使用样例数据，但交付时标明模拟边界。

## 看实际产物，按风险验证

按最小充分原则选择检查，避免每次照表执行所有项目：

- 样式或布局修改：看目标界面实际渲染；选择会暴露此次风险的尺寸、文本长度或场景背景。战斗 HUD 需要关注明暗背景和中心遮挡；管理界面关注真实内容密度、长中文与溢出。
- 交互修改：走通受影响的操作及相关失败/取消路径，检查焦点、输入穿透或重复提交等具体风险。
- 脚本修改：完成必要编译检查；只有涉及游戏运行状态、联网结果或生命周期时，才增加相应运行验证。
- 只有代码、静态预览或截图时，如实说明它们分别证明什么。网页预览不证明 Unity 已接入；截图不证明交互、网络或性能。

能查看截图时判断层级、可读性、题材一致性和状态辨识，先修最影响操作的问题。修复后只复查受影响部分，确认后停止。缺少运行或截图能力时交付已完成产物并明确未验证边界，不虚构视觉评分。

## 交付

简短说明设计方向、具体改动、真实接入情况、验证结果与仍需用户验收的部分。遵循项目已有提交与推送约定，保留其他人的并行修改。

本目录其他 `references/`、`scripts/`、`assets/` 和 `library/` 保留自上游网页 skill。它们不属于当前游戏 UI 的必需工作流：不要自动运行网页 `lint.mjs` / `inspect.mjs`，不要用网页禁用样式、图片或动画配额判定游戏界面。只有明确需要网页研究或素材工具时才按需查看；网页研究结论不能宣称已在游戏中验证。
