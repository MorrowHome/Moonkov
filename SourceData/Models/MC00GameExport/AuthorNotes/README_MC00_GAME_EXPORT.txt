
MC00 游戏导出派生版 / 使用与编辑说明

1. 文件与坐标
这是作者 v7 的独立 MC00 派生版，仅含 MC00，不含基地其余建筑或场地。原作者版保留完整来源对象与修改器。本文件可直接查看、编辑，无需执行任何嵌入脚本。
MC00_ROOT 的世界位置仍为 (58,-78,0)，保持原地图坐标；接入时替换或隔离旧 MC00 对比，避免新旧两套同时启用，也不要再次叠加这个偏移。楼层 0.6 / 6.6 / 12.6 米为来源元数据，不是需要再加的位移。新增组织根不改变原嵌套运动链。

2. 选择导出内容
可见模型：从 MC00_GAME_EXPORT 选择当前可见且未禁用渲染的物理几何，并保留需要的父根。32 个旧 L22 休眠件默认在视图和渲染中禁用，应排除。展示相机和太阳已移除；FONT/CURVE 仍可编辑，实际格式导出时需明确求值转换。
碰撞代理：单独按 MC00_COLLISION_PROXIES 集合导出；代理默认眼睛隐藏、禁止渲染，不应混入可见模型或因为“只导出可见对象”而漏掉。使用显式代理选择或导出副本检查世界坐标，不要通过叠加 root 偏移修正。不要将整个代理集合设为禁用视口求值来代替眼睛隐藏。
灯锚点：按需要导出 118 个 LIGHT_ANCHORS 空锚点及其父链。不要一次删除所有 Empty。三类数据应分别选择、分别计数。

3. 几何、资源与单处修改
已整理的静态 pack 是可编辑的求值网格，未焊接无关来源；源对象到输出的映射、顶点/面范围、原始枢轴和修改器栈见 MC00_SOURCE_TO_OUTPUT.json。需要拆回来源时按范围与作者 v7 回取；合并件不承诺保留所有原修改器的实时调节能力。
共享 Mesh 的各对象变换独立，但编辑 Mesh 数据会影响同族实例；只改一处时，先 Make Single User 或复制 Mesh 数据。严格资源共享不等于引擎已经启用实例化。自定义法线保留时存在 Blender 编码的微小量化误差，不能称为比特完全相同。

4. 门、抽屉、工具
原运动根及限制保留在 Blender：四个 MC107 滑门叶根的局部 X 限位、两个 MC108 抽屉的局部 Y (-0.65..0) 限位、两个中间滑轨的 drawer_y*0.5 驱动、三个可编辑工具根及锁定。详见 MC00_MOTION_CONTRACT.json。
格式导出不会自动生成 Unity 交互逻辑。本地需按源坐标基底重建限位、联动、取放和碰撞，并检查完整行程；不要将门叶、工具或运动链并进静态建筑碰撞代理。

5. 材质与双 UV
保留原材质、图像及 UV 层。MC105_REST_back_pad 和 MC105_REST_fitted_seat_cushion 的 MC106_Portable_BakeUV 是 active/render UV；内部 glTF 验证其法线贴图使用 TEXCOORD_1。转换时应检查材质实际选用的 UV，不可全部强制为 UV0。内部 GLB 是保真验证样本，最终接入格式由本地项目确定。

6. 建筑碰撞代理
建筑代理状态：已生成独立建筑碰撞几何，原生几何与有限通路自检已记录；不是Unity Collider自动配置或性能结论。实际覆盖 3252 个作者来源，生成 277 个代理对象，共 45728 三角面。
覆盖对象限于明确的固定建筑：原主楼板、分段外壳、固定内墙及入口墙面、具名梯段与相应护栏、平台及实际对应护栏、入口地板/坡道、明确固定门口框套。来源的长楼板/背板和跨楼层梯段保持原几何范围；合并代理使用 MC00_ROOT 基准，原来源枢轴只在来源范围映射中保留，不是每个来源仍有独立输出枢轴。同一代理仍可含多个独立闭合岛，分组不等于布尔实体合并，也不把楼梯改成斜坡。
L11/L21 有 8 个名称截断、身份尚未确认的门口来源条目未纳入代理；原可见几何保留。这是碰撞覆盖缺口，不能视为完整建筑或全部开口已验证，不能用自动 Convex/凸包封洞代替确认。
代理只是几何数据，尚需本地配置静态 non-convex MeshCollider 或经验证的适当组合，并检查引擎限制、控制器通过、台阶/坡度、门口净空与 NavMesh。不得对含门窗开口或多闭合岛的整组自动 Convex，以免填平通道。没有为这些代理配置 Unity 刚体/碰撞层/烹制参数。
使用 MC00_COLLISION_REPLACEMENT_COVERAGE.json 核对来源→代理→当前 render 输出。仅对被明确完整覆盖的原 render 碰撞禁用或替换，避免同位置重复碰撞；部分覆盖的输出需单独保留未覆盖部分，不能整对象取消。未覆盖区域和动态物体应独立处理。

7. 灯位与引擎灯光
118 个锚点保存位置和朝向：forward=-local Z，up=+local Y。当前原生文件没有这些作者 Light 数据块；物理灯壳、遮光件等仍是可见几何。
MC00_LIGHT_REFERENCE.json 保留原 Blender 灯参数供参考，并用 fixture_host_output_object / physical_fixture_output_objects 指向当前实体；source 字段只作来源追溯。engine_parameters 尚未配置，不可把 Blender 功率直接当成 Unity 强度。本地需设置灯型、单位、范围、阴影与烘焙。

8. 当前状态与本地验收
可见模型几何对象 9140 个，其中默认可见 9108 个；可见模型几何共 949110 三角面，其中默认可见 948678 三角面。
可见模型与碰撞代理的对象数、资源数、三角面数必须分开比较。文件只含 MC00，不能拿它与整座基地作者文件的大小差当成优化比例。Blender 对象/网格计数不等于 Unity Renderer、batch、draw call 或 FPS；更大的碰撞组也不保证更快。
尚未生成 LOD、法线/细节烘焙；尚未完成 Unity 灯光配置、实际碰撞/交互/NavMesh 验证与运行性能测试。
本地至少检查：同视角下的形状、材质和两套 UV；门/抽屉完整行程、工具取放和人物通路；在相同分辨率、光照和可见范围下，用 Profiler 比较 Renderers、批次和 CPU/GPU 时间。

9. 内嵌资料索引
MC00_SOURCE_TO_OUTPUT.json：来源→当前输出、pack 范围、共享资源、来源枢轴/修改器记录。
MC00_MOTION_CONTRACT.json：原生运动根、限制、驱动与本地重建依据。
MC00_LIGHT_REFERENCE.json：灯位/朝向、来源参数及当前灯具输出关系。
MC00_BUILD_COUNTS.json：最终原生实测计数，分别列 render_only、proxy_only、combined 及代理生成/引擎配置状态。
MC00_RENDER_STAGE_COUNTS.json：完整原样保留的早期 render-only 阶段记录；其中 colliders_generated:false 仅表示当时尚未生成代理。
MC00_COLLISION_SOURCE_RANGES.json / MC00_COLLISION_REPLACEMENT_COVERAGE.json / MC00_COLLISION_GAPS.json：代理来源范围、原碰撞替换覆盖和未覆盖项。
嵌入的制作脚本仅为来源记录，依赖云端 audit/source 文件路径，不是可在本地一键重建的打包工具。查看或编辑本 .blend 无需执行它们。

Blender查看提示：游戏版没有作者灯光和展示相机，可用Solid或Material Preview检查；不要因为渲染视图变暗而把展示Sun重新纳入导出。
