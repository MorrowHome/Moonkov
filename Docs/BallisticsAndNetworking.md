# 实体弹道与远端显示

Halo / Revolver 使用现有 Projectile ghost，每发独立存在。服务端记录发射 tick、初始位置、初速度；客户端立即创建预测弹体，收到同一输入 tick、同一武器的服务端实体后接管，写入正常 ghost 生命周期以便正确清理。远端从插值时间线计算飞行位置。网络射击不再显示原来的 HaloBoltPool 长光束。

轨迹使用 `p(t) = p0 + v0*t + (0,-g,0)*t²/2`，初始位置和方向均来自共同的 `PlayerGhost.GetShotRay`，不再分别从光环位置和眼前半米发射，也不做不同的近距离收束。每 1/120 秒细分曲线并扫描上一位置到下一位置，选择最近的非自身碰撞体。碰撞半径与弹体显示大小分开，服务端负责扣血；客户端碰撞仅隐藏预测显示。暂未加入空气阻力、穿透、跳弹或历史命中体回溯。

参数直接在 `Assets/DollSinger/HaloWeapon.asset` 和 `RevolverWeapon.asset` 的 Inspector 中调整：

| 字段 | 当前配置 | 含义 |
| --- | --- | --- |
| Type | Projectile | 实体弹道 |
| ProjectileSpeed | Halo 300 / Revolver 330 | 初速，米/秒 |
| ProjectileGravity | 1.62 | 月球重力加速度，米/秒² |
| ProjectileRadius | 0.005 | 碰撞扫描半径，米 |
| ProjectileLifetime | 3 | 最大飞行秒数，命中即停止 |
| ShowProjectileBody | 开启 | 短小发光弹体，不是连接目标的激光线 |
| HitscanRange | 1000 | 取得镜头瞄准目标的距离；弹道射程由初速、寿命及碰撞决定 |

没有为每发子弹增加 Rigidbody 或帧间 RPC。旧模板火箭默认重力为零，继续沿直线飞行；范围伤害按角色实体去重，避免头、身体、移动胶囊分别重复扣血。

## 远端动作延迟

用户已更正现象：本人的操作响应正常，其他客户端观察到动作滞后。已去掉网络动作参数上的第二层速度缓动及额外方向参数阻尼，保留本地演示的缓动。

本轮尝试的输入采样、固定步骤调度、插值缓冲覆盖已撤回，恢复模板原有网络时序。曾用 `new ClientTickRate()` 创建配置，只设置插值字段；该结构体其他字段全为零，阻止 `NetworkTimeSystem` 使用官方默认值，遗漏预测/插值时间缩放范围及纠正参数。加入方反馈反复回滚 10～23 个 tick。现不创建这份覆盖配置，由 NetCode 使用默认配置；将来如确需覆盖，必须从 `NetworkTimeSystem.DefaultClientTickRate` 初始化并验证有效参数。

用户已确认预览场景没有重复加载，为该现象追加的 UI 修改已撤回。

网络状态显示原始 RTT、`Frame`（实际渲染帧耗时）以及 `Snapshot gap`（预测 tick 与最近收到服务端快照的差值）。该差值包含正常预测提前量，不应直接当成单向网络延迟。

验证入口 `Moonkov/Checks/Ballistics`：检查月球下坠、分帧一致性、首段近墙碰撞、自身过滤、不提前判定下一段及武器配置。额外检查预测弹体的身份和生命周期登记。未替用户启动 Play；原先约 0.4 秒的实际远端滞后是否完全消除，需要运行两个客户端观察与读取帧耗时/快照数据，不能用 Edit 模式帧时间替代游戏性能数据。
