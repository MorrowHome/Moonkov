# 局内七部位健康与氧气

局内按 Tab，使用顶部「装备」「健康」切换。健康页显示七部位独立血量、人体伤情颜色、总健康和宇航服氧气；选择右侧受伤部位后点击治疗，消耗口袋或胸挂内的一支医疗注射器，为该部位恢复最多 40 HP。原有 `[4]` 和装备物品右键医疗仍可用，由服务器选择受伤比例最大的部位。

## 运行规则

| 部位 | 最大生命值 | 归零后果 |
| --- | --- | --- |
| 头 | 35 | 死亡 |
| 胸 | 85 | 死亡 |
| 腹 | 70 | 继续受到的伤害分摊到仍有生命值的其他部位 |
| 左右臂 | 各 60 | 武器装填与射击间隔乘 1.4；后续伤害分摊 |
| 左右腿 | 各 65 | 禁用冲刺，移动速度乘 0.65，跳跃高度乘 0.5；后续伤害分摊 |

总上限为 440。这是新的部位生命值总和；枪械原有伤害数值保持原值。头或胸归零时，派生的总健康直接为 0，沿用已有死亡、尸体、结算和 AI 状态路径。其余部位的溢出伤害按剩余生命值比例分摊，不丢失重复击打已归零部位的伤害。首版注射器允许恢复归零的非致命部位；不引入手术、出血、饥渴或跨局伤情保存。

健康在服务器生成玩家和人形 AI 时初始化；死亡后重新部署恢复满值。`CurrentHealth`、`MaxHealth` 是七部位状态的兼容派生值，运行时伤害和医疗统一使用 `RaidHealth`，不要直接扣减或恢复总血量。真实投射物和 hitscan 都使用服务器物理命中的位置判部位，客户端不提交命中部位。头与外侧手臂有显式查询碰撞体；胸、腹和双腿依据权威身体胶囊与身体朝向分区，属于几何命中区域，不是逐骨骼碰撞或布料蒙皮碰撞。区域尺寸跟随身体控制器，服务器不依赖被禁用的模型动画。

HUD 危急颜色和 PMC 的受伤撤退判断取总健康、头部、胸部剩余比例中的最低值，避免四肢还有大量血量时掩盖头胸的致命风险。

当前范围爆炸沿用一次实体伤害的路径，作用于胸部；未来新火箭的遮挡、衰减和多部位分配另行设计。

## 氧气与有氧区域

正式月球战局中，服务器推进玩家氧气；Tab、暂停菜单和 UI 关闭不暂停战局生存时间。AI 不消耗玩家的氧气系统。氧气默认 100%，室外连续消耗 600 秒耗尽；25% 以下提示，10% 以下危急，耗尽后经过 8 秒宽限，以每秒 3 点损伤胸部。低氧提示在不打开 Tab 时也可见，并以现有提示音分级提醒。进入有氧区域立即停止缺氧伤害，每秒补充 5%，离开时保留余量。

这些参数在正式场景 `Moon Raid / MoonRaidMap` 的 **Survival (server authority)** 分组调整；无需修改玩家预制体。部位上限与伤情系数在 `RaidHealth.cs` 中维护，当前是首版参数，尚未进行完整战斗平衡验收。

为真实加压室内创建一个空物体，添加 `BreathableZone` 和触发式 `BoxCollider`，使盒体覆盖房间内部。支持旋转、缩放、重叠区域与启停；服务器按角色躯干位置判断，不依赖客户端触发消息。普通屋顶或建筑碰撞体不自动成为有氧环境。当前开放月面没有新增有氧室内区域；后续基地应按上述方式标出加压房间。

## 医疗与复制边界

七部位、氧气、有氧状态通过已有 `PredictedPlayerGhost` 的 Ghost 字段复制。UI 只读取本机拥有的玩家；伤害、氧气推进、死亡与医疗结果由服务器决定。医疗 RPC 仅增加目标部位，复用连接所有权、战局 ID、请求序号、库存版本、可访问性与原子消耗校验；死亡、满血、非法部位和过期库存版本不会消耗医疗。请求未确认期间禁用重复操作，超时通过已有库存确认路径恢复交互。

装备图标修复包含两个原因：局内通用按钮样式覆盖了装备槽位的百分比高度；装备绘制元素没有固定填满其绘制容器。现在保留槽位高度，并让图标覆盖可用绘制区域，背包网格交互保持原有逻辑。

## 验证

- Unity Editor 编译成功；`Tools / Moonkov / Check Raid Health` 覆盖七区域与左右识别、部位死亡、危急状态、溢出伤害、伤腿移动、定向/自动医疗、过期版本与死亡拒绝、缺氧宽限跨帧、室内恢复、旋转有氧区域和生成的医疗 RPC 序列化。
- 单 Editor 的 Play Mode UI 检查确认健康页中文、人体与血条显示；点击选中左腿并治疗后从 0 变为 40；装备图标实际渲染且绘制区域非零。
- UI 检查使用临时状态与物品，不修改个人仓库或保存场景。它不替代正式月球战局的实弹命中、地图有氧区域与 Host/Client 双端验收；未做完整构建或性能测量。

布局和颜色分别在 `Assets/Resources/Moonkov/UI/RaidHealth.uxml` 与 `RaidHealthStyles.uss`，可用 UI Builder 调整。UXML 和 USS 使用不同资源名，避免 `Resources.Load<StyleSheet>` 错误选到 UXML 的内嵌空样式表。
