# 受伤与生存视觉反馈

分支 `feat/injury-survival-feedback` 基于 `feat/pmc-combat-response` 的 `1c407cc5`。沿用现有 DamageVisualsController、玩家 Ghost 状态、URP 全屏 Pass 和生存 HUD，不需要场景或 Prefab 重新绑定。

## 玩家看到的反馈

- 真实身体受击：短促的全屏红色冲击、边缘血珠和血痕。伤害越重，冲击越强；血痕比闪红消退得慢。连续受击可叠加。
- 濒死：持续红色染色、边缘分叉血丝和双峰心跳式脉动。危险程度取总血量、头部、胸部剩余比例中的最低值，避免四肢尚好掩盖胸部濒死。低于约 55% 开始显现，约 8% 接近最大效果；中心仍保留瞄准可读性。
- 饥饿／饿死前：低于原有 25 点警戒线逐渐失色、偏暗褐色，周边视野随虚弱节奏压暗；能量耗尽时最强。伴随现有真实 HUD 生存警告，不凭空显示枪伤血丝。
- 脱水／渴死前：低于 25 点逐渐苍白、褪色；边缘有轻微热扰动及色差重影，耗尽时最强。中心不发生瞄准位移。
- 治疗、进食和饮水改善对应真实资源后，效果平滑退去。死亡保留短暂濒死余韵，约 1.1 秒后释放画面；新生命重置历史状态。首次加入已受伤／死亡角色不会重播旧受击。

完全由护盾吸收的攻击沿用原蓝色护盾反馈，不生成身体血迹。小额全身代谢损伤依据已有 LastHitPart、LastDamageAmount 和资源状态识别，不再每 tick 重播枪伤红闪和身体击中音；现有 Ghost 没有新增伤害来源字段，因此该区分只覆盖可由这些状态识别的代谢损伤。极速赏金暂停的营养资源不产生饥饿／脱水滤镜，伤后生命上限变化按当前可恢复部位上限归一化。

## 实现与成本

`InjuryFeedbackState` 是本地展示历史，只读取现有状态并按单调受击 tick 去重，包含同帧、旧快照回退和重新收到同一受击的保护。伤害展示脱离动画事件更新，第一／第三人称仍使用拥有者实际相机；不修改伤害、资源消耗、相机姿态、输入或网络协议。

`InjurySurvivalScreen.shader` 在既有 RenderPassEvent 602 使用 URP 正式颜色副本，避免同一目标读写；只向本机拥有者的主相机排入，跳过叠加相机，正常状态不排入受伤 Pass。现有黏液镜头效果保留。HUD 沿用独立 UI Toolkit 渲染与交互。

血丝和血珠由固定种子 73951 的原创分叉笔触生成，512×512 线性 RGBA 纹理约 1 MiB，由引用计数共享；准备本机展示时生成一次，不逐帧创建纹理或材质。禁用和销毁时解除渲染回调、释放私有材质及共享纹理。组件保留原序列化字段和触发 API，新增 `effectStrength` 为 Inspector 内 0–1 强度控制。

## 验证边界

复用单一 Editor 完成编译、Shader 检查及 `InjuryFeedbackChecks.Validate()`：真实身体受击、历史／预测重放去重、护盾全吸收、代谢掉血、致命部位危险值、治疗和饮水恢复、极速赏金营养暂停／上限归一化、致命首击、死亡淡出、复活和共享资源释放均通过。

`InjuryFeedbackChecks.CaptureFormalMap(outputDirectory)` 临时打开正式 `TheophilusGameScene` 的预览场景，使用实际 URP 全屏 Pass 生成正常／受击／濒死／饥饿／脱水及四格对照图。捕获包含临时中性补光、关闭后处理，不代表正式对局的最终照明；结束后关闭预览并释放资源，保留原 MainMenu 编辑场景。

未启动 Play、服务器、独立客户端或第二个 Editor；未覆盖动态战斗、实际 HUD 合成、所有相机切换、目标设备 GPU 性能或声音听感验收。静态图不能证明心跳节奏与动态辨识已经完成实战验收。
