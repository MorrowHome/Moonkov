# 生命体征监测

最终参考为 `Docs/Planning/UI/HealthHUD/approved-reference.png`，即用户附件中的竖向医疗扫描仪。旧七块矩形格子人形和旧 SVG 草稿已废弃。以实际图片为准，不按此前的方案字母推断。

- HUD 和 Tab 共用 `RaidVitalsMonitor`。扫描人体、右侧动态心电图、底部氧气、能量、水分、胃容量放在一起。HUD 没有黑底和仪器外壳。身体没有部位名称、血量数字或说明图例。
- `RaidBodyDiagram` 使用参考衍生的蓝白扫描贴图。17 块视觉分片映射原有七部位。血量同时控制颜色和亮起面积。胸部上下两块已合成一块。头、胸、腹从四周向中心缩小，亮区面积对应剩余血量。四肢按整个部位共用一条截线，从末端向近端退减；不能让上臂、前臂、手掌分别填一次。暗色完整轮廓保留，使用真实动态上限。
- Tab 仍通过人体选定治疗部位，沿用原治疗和消耗品请求。HUD 不接收输入。局内监测常驻，背包和暂停时隐藏。旧独立氧气面板隐藏，原警告音规则保留。
- 心电图约 30 Hz 刷新，只读已有状态。隐藏、暂停和脱离面板后停止刷新；设置中可以关闭动态。波形节奏用于表现压力，不是新增的真实心率数值。没有新增网络或存档字段。身体和资源显示只在数据变化时更新。
- 37 项身体显示检查和 18 项生命波形检查通过。Unity 编译通过。定向检查入口为 `HealthBodyChecks.Run()`、`RaidVitalSignalChecks.Run()`。原健康、营养和氧气规则回归已通过。原生窗口验证了部位选择、治疗目标、忙碌和缺物品禁用，以及氧气、食物、饮水请求。
- 预览入口为 `Tools/Moonkov/Review Vital Monitor`，使用实际运行时控件与样例状态，不写玩家档案。截图在忽略目录 `LocalData/VitalMonitor`。本轮未进入真实战局、联机或 Player 构建验收。

## 美术来源

整体监测布局参考保存在本目录 `approved-reference.png`。人体以用户最新确认的单块胸部图片为准，已经直接接入运行时素材。运行时素材为 `Assets/Resources/Moonkov/UI/MedicalScan/BodyScan.png`。它由内置 image_gen 工具根据参考生成，不是逐像素裁切。提示要求保留参考中的人体比例、分片布局、蓝白扫描网格与透明背景，移除仪器外壳、波形、标记和文字，并使所有部位处于健康状态。随后按用户确认，将上方两块胸部合成一个连续扫描面，保留其余部位布局。运行时再根据真实血量控制颜色和填充。

几何文件只记录贴图各分片的透明通道边界，用于遮罩和选择。它不重新绘制人体。所有实例共用同一张纹理，不逐帧生成贴图。
