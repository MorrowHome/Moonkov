# Bounty Clash 赏金速战实施契约

2026-10-21，用户明确选择 Bounty Clash，要求完整复刻其玩法流程。协调：副程序。本文件描述目标，不代表以下项目已经实现或验收。

- [官方 Steam 公告汇总](https://store.steampowered.com/news/posts/?appids=594650&enddate=1734536209&feed=steam_community_announcements)：赏金带出后剩余回合时间缩短为90秒，单人/双人赏金加成。
- [官方开发者介绍](https://www.huntshowdown.com/news/bounty-clash-developer-insight)：队伍上限调整；该页曾提出9人，不应把历史提案视为最终规则。[后续官方团队更正](https://www.reddit.com/r/HuntShowdown/comments/1iii0bt/)保留12人、最多4队。
- [规则补充参考](https://huntshowdown.wiki.gg/wiki/Game_Modes/Bounty_Clash)：每队1–3人、两个撤离点、越界20秒、携带者暗视5秒、撤离30秒。此为社区资料，具体数值需要标明来源，不能把未查证参数写成官方事实。
- 使用Moonkov角色、武器、库存和月面美术；复刻模式玩法。原项目没有猎人招募/血脉XP系统，因此不伪造已有此类系统。新增模式的具体适配及尚未实现差异必须在交付时逐项说明，不用“完全复刻”掩盖缺项。

## 玩家闭环与必要行为

1. 主菜单显式选择原搜打撤或赏金速战，玩法与Host/Join等连接方式分离。Host/独立Server决定模式，客户端加入时校验模式/规则版本。旧默认仍是原搜打撤。
2. 使用现有账号、仓库、自备装备出战。新增服务器权威的赛前队伍/准备状态，单人、双人、三人队；最多4队/12人。不能让客户端随意指定TeamId抢占他人队伍，采用服务器管理队伍及加入许可。不另造全球匹配服务。
3. 所有人共享唯一MatchId、开始时刻、900秒截止时刻及终局；每人的DeploymentId/SettlementId继续独立。至少两队准备后开局，服务端锁名单；进行中禁止新参战者，只允许原账号重连。单机入口不能伪装成已经实现多人对局。
4. 单个紧凑据点，周边四组安全出生位、两个独立撤离点，开局目标已死亡。边界20秒宽限后淘汰；目标/撤离点有明确标记。不允许通过原地图单撤离点或个人重新部署绕过本局规则。
5. 靠近目标发起驱散，服务器检查存活、距离和视线；驱散启动后全局公布并持续推进，只生成一份赏金。驱散时长使用显式版本化参数（若无法查明原版精确值，记录选值及差异）。驱散恢复队伍伤势的行为由生命系统实现并验证。
6. 赏金由服务器独占持有；拾取必须近距有效操作，倒地/死亡时掉落，敌我均可争夺。地图/感知提供携带者的大致位置，不能直接永久公开所有敌人精确坐标。携带者具有总计5秒的增强感知，按服务器时间消耗；信息仅发送给获权接收者。
7. 队友标识、减伤友伤、倒地救援。倒地保留实体/装备，禁止移动、开火和物品操作，不能立即走旧死亡扣装/复活管线。救援须同队、距离/视线、持续交互、受伤/离开中断；反复救援降低可恢复生命上限，终死/团灭后才走损失结算。爆炸友伤与普通子弹区分。赏金救援额外规则、燃烧尸体和特质若未覆盖，必须列明，不能称已复刻。
8. 两个撤离点各自30秒持续撤离；敌队进入阻挡区域或队友倒地阻止撤离，离开重置，不能复用8秒单人无阻挡撤离。同区队友一并撤离；无赏金也可撤离并保留实际带出物品，赏金奖励仅授予实际合法撤离参与者。
9. 唯一赏金撤离后截止时刻取原截止与当前+90秒的较小值；不会延长快到期回合。超时者损失本局装备，不因只剩一队就自动获得赏金或免费撤离。所有参与者结束后清理本局临时对象并可准备新回合。
10. 掉线保留原参与者/账号身份与既有出战，重连不能新领装备、换队、重复赏金。具体保留时限与角色处置明确记录。重启沿用现有outbox，不承诺恢复尚未持久化的整张战局。

## 持久化与项目适配

- 延用原自备装备扣除、整树返还、待领取区及幂等收据。Mode/RulesVersion/MatchId由服务器绑定至出战，最终结算必须对应登记的参战身份；旧后端必须拒绝新模式入口，不能忽略新JSON继续普通模式。
- 赏金是模式权威目标，不能从客户端提供的普通物品/金额换取收益。领取、倒地、救援均不是奖励到账事件，只有经验证的最终带出裁决可发奖。多玩家/重试/重启不能重复兑现同一份赏金。
- Moonkov以月尘承接赏金经济；具体基础赏金与单排/双排加成使用明确配置，来源和适配记录清楚。原MC00任务首次奖励不能被模式目标误触发。
- 新模式关闭普通随机任务、正常Boss战、PMC与原搜打撤氧气/饥渴惩罚；可保留低密度原生PvE作为据点干扰。保留项目武器、治疗和物品操作机制。此为本项目实现决策，不冒称Hunt具有月面机制。
- 用户Windows服务器和数据库当前关闭，本轮不尝试SSH或线上部署。需要数据库验证时使用隔离测试环境，不能触碰真实账号、存档或Prefs。

## 文件所有权与执行次序

- 服务端主组（原AI对话）：新增Shared/BountyClash规则/协议、ServerGameSystem.BountyClash与核心ServerGameSystem/Raid、Team/生命/四条伤害管线。先冻结API/协议和状态机，再发下游接入；不得修改库存持久化组文件。
- 持久化组（原库存对话）：ServerGameSystem.Persistence、RaidPersistenceContext、Backend、离线兼容、结算与协议DTO。消费服务端终局，不修改主组状态机或入口UI。
- 地图组（原地面包对话）：BountyClash场景配置/锚点/出生/边界/撤离表现，MoonRaidMap、AI spawn模式过滤，独立安全接入。不得重写正式地图原模式配置或修改主组协议。
- 界面组（原瞄准对话）：入口模式与队伍准备、客户端状态、HUD/地图/暗视表现、队友倒地与救援提示、结算页面。消费冻结协议；不擅改共享协议和后端。
- 副程序：规则契约、冲突协调、审查与验收记录。Unity运行态与Git提交依次授予，每组只提交本任务相关文件并push当前develop；不强推，不混入别组未完成修改。编译有依赖时可阶段集成，不把半成品报告为完成。
