# 单人战役完整策划

版本：设计提案 v1.0，2026-10-25。状态：故事方向已确认，当前只实装第一章教学版。

用户已要求先完成第一章，用于教学和背景引入。所有建筑仍按未定稿处理，任务使用可重绑的语义锚点。实际接入与验证范围见[第一章教学版接入记录](ChapterOne-Status.md)；后续七章和返航仍为策划。

单人战役以调查式搜打撤为基础。玩家受雇进入失联的月球研究站，逐步查明事故与公司的责任，阻止污染样本被运走，最终携带完整证据乘飞船返回地球。八章故事、24 个主线任务和 8 个可选支线共同组成一条有终点的流程。

本总纲描述完整八章目标，不代表运行版本已经具备所有内容。用户已确认故事梗概和章节方向，最终目标为携证乘船返回地球。当前实施边界为第一章，其他证据、设施变化和返航演出留待后续逐项实现。

## 阅读顺序

1. [完整故事正文](Story.zh-CN.md)：从抵达研究站到地球隔离着陆的连续叙事。用于评审人物、因果和情绪推进。
2. [全部任务策划](Missions.zh-CN.md)：全部主线和支线。每项列出玩法步骤、追踪文案、保存条件、失败恢复和奖励。
3. [任务系统规格](System.zh-CN.md)：任务定义、章节调度、追踪、存档、证据、终局恢复与实施验收。
4. [剧情呈现与制作清单](Narrative-Delivery.zh-CN.md)：把故事分配到通讯、现场和物品，明确场景与返航所需资源。

正文回答故事是否成立，任务册回答玩家具体做什么，系统规格回答这些行为如何被承认和保存。三者使用相同章节、任务 ID 和证据含义。具体字段与保存裁决以系统规格为准；叙事正文不替代游戏规则。

## 战役的成功标准

- 玩家能说清自己受雇来做什么，何时产生怀疑，为什么反抗，以及最后阻止了什么。
- 每次出战都有可执行的当前步骤。恢复设备、调查取证、携带回收、隔离线路、准备飞船和最终返航形成不同玩法。
- 装备、物资和路线知识帮助完成下一段行动。主线不依靠重复刷材料、刷击杀数或等待随机事件出现来延长时长。
- 追踪之后，局内显示任务与当前动作。取消追踪只隐藏引导，有效行为仍会记录。
- 主角确实携带证据登船、离开月球，并在地球完成隔离着陆和证据交接。到达地球后才记录战役通关。

## 世界与人物

### 研究站和污染

研究站沿用 Theophilus，MC00 为科研设施。站内开展月核异常场研究，并把研究扩展到生物和人员试验。污染体包括研究人员与实验生物。敌人身份不因主角反抗就改成新的公司佣兵。

污染组织依靠试验场与活性样本的异常联系维持活动。普通武器难以终止这种联系。Battle Halos 用电池供能，发出能干扰联系的脉冲；它源于同项目的场控制技术。正式战役不要求先实现一套普通枪械无效或组织无限再生的战斗系统。

光环武器本身不装载活污染样本。断开主试验场能阻止公司继续驱动实验，但不会自动治愈感染人员或让全地图敌人瞬间消失。残留污染区仍需隔离。结局只确认本次转运和继续试验被阻止。

### 清理员

主角是清理队现场成员，由玩家选择现有角色。故事不固定性别、实名或角色模型。初始动机是完成合同并平安返回，随后是查清自身风险，最终主动承担把证据带回去的责任。

主角独自进入站内。其他队员的存在通过飞船保障与通讯表达，不新增必须跟随的 AI 队友。玩家可以跳过对白，任务目标仍清楚。

### 沈禾

沈禾是飞行工程师，留在月面的作业船保障舱。沈禾需要保护返航条件，起初劝主角少冒险；证据明确后，选择一起摆脱公司的远控。角色通过通讯与船内呈现出场，不承担地图护送或自动打怪功能。

### 许砚

许砚是已经死亡的研究员。许砚参与过试验，曾在风险出现时妥协，后来试图保存数据并救出同事。许砚不是预知一切的解释者，也不通过录音给主角实时回应。各段录音的录制时刻与播放时刻明确分开。

### 顾衡与远穹工业

远穹工业和顾衡为暂定创作名。顾衡是远程项目主管。公司推动了危险试验，隐瞒已知风险；事故确实失控。失控后，公司选择保留成果、限制人员离开，并要求清理队毁证。

顾衡最初提供有用指引，并以防止污染扩散解释封锁。公司的责任由独立记录逐步证明。顾衡的通讯用于施压和作出命令，不承担独白交代全部真相的功能。

## 事故时间线与证据边界

| 时刻 | 发生的事 | 可证明的范围 |
| --- | --- | --- |
| 事故前数周 | 试验出现异常，许砚的风险报告进入公司记录；试验继续扩大 | 公司收到风险信息，不等于事故由公司故意制造 |
| 18:34 | 设施记录异常预警 | 系统已有危险信号 |
| 18:39 | 公司命令关闭人员通道 | 封锁命令早于首次求救；单凭封锁不能排除防扩散解释 |
| 18:42 | 配电 A 出现热损 | 沿用现有铭牌含义，不改成“此时全站已死亡” |
| 18:44 | 首次求救发出 | 与门禁记录组成独立先后顺序 |
| 18:47 | 备用母线带电 | 沿用现有铭牌含义，需结合线路图判断它给什么供电 |
| 事故后 | 公司下达优先回收成果、删除异常和人员记录的清理指令 | 签名命令与风险账本、设备记录共同证明公司责任 |

18:42 与 18:47 是两柜的五分钟设备差异。18:39 与 18:44 是封锁先于求救的另一条五分钟证据。叙事、字幕和任务提示不得把两者合成同一事实。

生命维持与试验回路的分离图，是判断备用供电用途的必要补证。玩家在第二章只能提出怀疑，第三章与第四章才逐步确认隐瞒与毁证。避免把合理检疫措施本身写成有罪证明。

## 证据与返航

| ID | 逻辑代码 | 含义 | 首次形成 |
| --- | --- | --- | --- |
| EV01 | `incident_blackbox` | 带设备来源签名的事故时间线，包含供电、门禁与求救记录 | CM04 至 CM06 |
| EV02 | `trial_ledger` | 风险报告、试验暴露记录与公司收到报告的回执 | CM08 |
| EV03 | `cleanup_directive` | 回收优先级与毁证命令的签名原文 | CM09 至 CM10 |
| EV04 | `shutdown_receipt` | 现场硬件停机、隔离与防重启结果记录 | CM23 |
| 包装 | `evidence_case` | EV01 至 EV04 的密封离线证据匣 | CM23 至 CM24 |

“原件”指保留来源签名、记录上下文和完整校验的数据。它不意味着数字证据绝对不能复制。船上离线备份保存前三份材料，证据匣用于最终实物交接。详细的取得、损失、重建与物品事务见系统规格。

CM17 只向地球公共信道发送求救、身份和证据摘要。完整数据没有因此完成交付。通信带宽与被干扰的条件在现场呈现，避免玩家不理解为何还需带证据返航。

返航使用停泊月面的同一艘作业船。船具有地月航行能力和足够燃料，主飞控原受公司授权控制。保障舱、仓库和本地制造独立运行，玩家反抗后仍可整理装备。日常撤离代表返回船的保障区，不等于已获准离月。

沈禾和主角恢复离线应急飞控，校准导航，取出公司预装的活污染样本并留月封存，再检查货舱、人员与装备。枪械电池只为光环与小型设备供能，不充当飞船推进剂。

终局让玩家进入真实登船流程，完成证据装船、关舱与起飞。航程通过受控转场表达，随后到达地球指定隔离地点，完成着陆、检查和证据交接。故事不宣告公司立即倒闭，也不以出现新反派抹掉本次胜利。

## 主线与重复游玩的关系

战役章节提供稳定的必要任务机会。物资、可选事件和有限遭遇可以变化。任务系统不能把下一章藏在小概率随机事件里，也不能要求为同一证据重复交付多次。

章节推进会改变任务用途、可用设备和部分已知路线。所有变化都要在场景中有对应表现，不能只在日志里写“基地已变化”。第八章完成后，战役档案停在地球结局。若开放继续搜打撤，应使用明确的“通关前自由行动”快照或独立档案，不在剧情上把主角悄悄送回月球。

主线失败沿用现有物品损失和保护容器规则。已经确认保存的章节不回退。未入库证据可在合格来源重取，不能出现唯一钥匙丢失导致整档卡死。终局不可逆操作、起飞中退出与通关提交的恢复边界见系统规格。

## 与现有项目的接入边界

现有基础包括独立单机档案、搜打撤、仓库与改装、MC00 月核取样和事故档案两种设施事件、局内详情和单项追踪。当前实现与证据见 [随机任务实施状态](../Missions/Implementation-Status.md)、[独立单机](../../SinglePlayer.md)。

新增内容包括跨局战役状态、版本化主线目录、多任务日志、持久追踪、章节调度、四证据校验、场景章态、返航设备与完整终局。现有飞船首页是菜单宿主，不能据此认为已有可登船、关舱和地月航行流程。

首个实施目标为独立单人本地档案。现有在线设施事件继续使用原规则，合作战役另行确定。不为本轮策划改动运行代码、网络协议、存档或正式场景。

## 评审与实施顺序

先评审八章因果、角色与结局，再评审任务是否有具体而不同的行为，随后确认保存和失败规则。通过后先做第一章至第二章的可玩闭环与持久追踪，再扩展中段章节，最后接入完整返航。实施阶段划分用于组织工作，不把任务后半段留成未策划占位。

每个实施任务按单一事项提交。沿用当前分支与原生 Git，不混入现有光环工作区修改。任何阶段都遵守单 Unity Editor、不做联机验收、只做与变化相关的最小必要检查。
