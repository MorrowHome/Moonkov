# 诗岸角色接入

诗岸作为额外角色接入，角色索引为 `4`（`GameSettings.ShianCharacterIndex`）。资源位于 `Assets/Shian`，原始可编辑模型位于 `ArtSource/Shian/Shian.blend`。沿用 Dollsinger 的角色表现、武器姿势和近战系统，初音及 Dollsinger 的资源保持独立。

## 可复现转换

使用 Blender 5.2.2 LTS 与 MMD Tools 固定版本 `e321bd02dd0288a3dc9f1974c06597803c060e11`，插件来源为 <https://github.com/MMD-Blender/blender_mmd_tools>。转换时不得另开 Unity Editor；以下后台 Blender 任务应与其他重型任务串行。

```sh
/Applications/Blender.app/Contents/MacOS/Blender \
  --background --factory-startup --python-exit-code 1 \
  --python Tools/Models/import_shian.py -- \
  --source /Users/morrow/Downloads/诗岸/诗岸.pmx \
  --mmd-tools /tmp/moonkov-miku-import/blender_mmd_tools-e321bd02dd0288a3dc9f1974c06597803c060e11
```

脚本复用现有初音转换器的 PMX 读取器，但独立输出诗岸资源。源文件头为 `PMX@`；只在内存和临时副本中将第四字节修正为空格，用户原件不变。有效的 16 张纹理完整复制；另两个乱码纹理引用没有材质使用，manifest 保留其未使用、缺失状态。

完整 MMD 骨架、约束、204 个刚体、301 个关节和原贴图打包在源 `.blend` 中。Unity FBX 只保留普通绑定变换、蒙皮和顶点表情，不导出 MMD IK、grant、物理或驱动器。运行时中间 `.blend` 写入系统临时目录，仓库不重复保存该大文件。

模型目标高度为 1.65 米；原网格最低点为约 0.00656 米，最高点为约 1.65656 米。manifest 记录缩放、原文件 SHA-256、坐标转换和所有保留骨映射。

## 骨架与动态链差异

源模型具有 334 根骨骼。转换后保留 274 根源骨并补 11 个发梢标记，总计 285 根。删除远离身体、无权重的调整控制骨及不再使用的普通腿控制链；加权骨及其必要祖先保留。

诗岸腿部的主要权重位于 `足D／ひざD／足首D`，与初音不同。因此把 D 腿直接规范命名为 `足.L/.R`、`ひざ.L/.R`、`足首.L/.R`，保留其原始绑定位置和朝向；`足先EX` 原本已挂在 D 踝下。普通股骨每侧另有 21 个加权顶点，其关节头与 D 股骨完全同位，这部分权重合并到 D 股骨并归一化。普通膝踝没有权重，不用于 Humanoid。D 膝踝与普通控制骨存在约 0.04–0.06 毫米的位置差，转换没有把加权 D 骨强行移至控制骨。

Humanoid 的腰、脊柱、胸、颈、头、双臂和三节手指采用现有规范名称。源文件自带 10 个指尖标记，显式保留，不重复创建。12 个 `腕捩1..3`／`手捩1..3` 加权辅助骨保持在对应腕、肘下，可由现有 `HumanoidTwistFollowers` 更新。源 grant 图不在运行时求解；动作烘焙与 Humanoid 驱动替代其用途。

源网格绑定为 A 姿势，上臂下垂约 37°。导入时须在临时实例中依次把上臂、前臂对齐角色横轴，并将该 T 姿势仅写入 `humanDescription.skeleton`。直接将原始 A 姿势当作 Humanoid 参考，会使共享待机的双臂向内、向后收，手腕落在背后；仅检查 Avatar 有效和蒙皮有限值无法发现这个错误。校准保留 FBX 网格、原始绑定和枪械精确姿势库，依赖 Humanoid 的 Quaternius 近战库须重新烘焙。

裙子使用同一套 16 条径向链，每条有 8 层骨（末层是终点），共 112 个可模拟段。11 条发链均有明确末端，合计 55 个可模拟段；长双尾各有 13 段。胸部使用 `胸上2.L/.R`，没有额外领带链或被动 offset 链。原 PMX 横向裙子约束不直接重建，运行时使用现有 `SecondaryBoneSpring` 与手、躯干、腿碰撞代理。

第一人称隐藏前缀为 `頭`、`目.`、`hair.`。眼骨必须单独隐藏：眼部材质是 `Face04/Face22`，不命中现有精确的头部材质名单。当前配置也隐藏完整长双尾，完整身体仍用于第三人称与影子。

## 材质与表情

保留 42 个材质槽，不合并透明叠层与实体表面。资源名含唯一槽号，另以 `semanticName` 配合现有头盔、身体和第一人称系统：主脸为 `Face`，主要身体为 `Body`，短发槽 9、30–38 为 `Hair`；两侧发圈和长尾分别保持 `Hair39/Hair40`，避免把整个长发范围计入头盔。服装使用 `Dress*`。

所有源材质均开启双面显示。主要材质沿用项目 lilToon 模板；源 PNG 的透明区域继续参与裁切；仅 PMX 标记启用描边的材质使用描边 shader，宽度为 0.0015，避免给原本没有描边的脸和裙褶额外画出接缝。`cheek` 的 alpha 最高仅约 0.502，需使用 lilToon 透明混合、关闭 ZWrite 与 ShadowCaster，不能当作普通不透明色块处理。纹理各向异性级别设为 0，遵循原包显示建议。主脸贴图保留 2048 尺寸，单独关闭块压缩和 mipmap：原半脸 UV 岛边缘留白很窄，默认压缩与低级 mip 会把透明区黑白颜色采到面中，形成灰白竖缝。纯白贴图、4096 原尺寸和最终 2048 无压缩／无 mip 的对照渲染确认该缝消失；没有为此修改网格、源贴图或其他材质。

170 个顶点表情完整保留，其中源文件仅有 59 个非空顶点表情，111 个为空占位。保留名称和 shape 不代表会自动播放所有表情。源文件另含骨、材质和组形态；运行时不模拟完整 PMX 形态系统，不把这些形态假报为已支持的 Unity blendshape。

## 源模型 QA 与导入差异

`ArtSource/Shian/QA/GeometryQA.json` 保存未掩盖的原始审查结果，`pass=false`。四角纹理、实体和线框图分别为 `Textures.png`、`Solid.png`、`Wire.png`。

原报告包含 22 个退化面、22 条零长边、3 处共边绕向异常、2 条非流形边、4,145 对近共面面、15 个采样到的零 UV 面积面，以及两块各 109 顶点的独立脸部岛。UV 检查对大网格采样，15 不是完整网格的精确总数。约 77.57% UV 重叠、12,785 对近重合顶点和开放边也保留在报告中，不能据此自动焊接原模型。

对 PMX 原始三角、材质与形态索引的只读复核给出了以下分类证据：

- 两块 109 顶点岛都属于材质槽 13（`ya_Baked`），位于双眼下方。每个顶点同时出现在 `涙`、`まばたき`、相应侧眨眼和笑脸等形态中。这是有意保留的眼泪／眼睑表情部件，桥接到脸部会破坏原表情。
- 22 个实际近零面积三角在原始 PMX 中已存在（世界面积阈值 `1e-12 m²`），其顶点未被任何源顶点形态修改。Unity 实际导入得到 145,664 三角，恰好比源／FBX 的 145,686 少 22，符合导入器剔除这些退化面的结果。源艺术文件不因此修改。
- 蝴蝶结材质槽 28 中有 170 对几何完全重合、同向、UV 不同的三角，未参与脸部形态。这能确认纹理叠层的存在，但不能证明所有重叠都没有闪烁；4,145 对近共面结果仍需结合实际渲染检查，不能全部归为表情面。
- 两条有三面相接的边位于手臂花材质槽 0，另一个同向共边异常位于身体槽 23。这些属于可单独审视的源几何问题，不应笼统解释为表情需求。保真转换未自动删面、翻面或焊接。

没有反向闭合岛、未加权顶点或超过四骨影响的顶点。原模型的眼部／装饰分件与纹理层可以有意分离，但这不等于通用几何检查通过。

## 生成与验证顺序

在现有唯一 Unity Editor 中顺序执行：

1. `ShianSetup.ImportModelAndExportBind()`，创建 Humanoid Avatar 并导出 `Tools/Blender/ShianBind.json`。
2. 普通 Python 执行 `python3 Tools/Blender/retarget_shian.py`，生成武器姿势与明确标为待烘焙的近战种子。
3. `ShianSetup.Build()`，生成本地、网络、菜单、尸体 prefab，注册角色索引 4 与独立演示场景。
4. `QuaterniusMeleeSetup.BakeShian()`，把近战动画烘焙到诗岸最终骨架；待烘焙种子不能作为完成品。
5. `python3 Tools/Blender/retarget_shian.py --validate-only`，检查数据、绑定摘要与近战已替换。
6. `ShianChecks.Run()`，检查动画、指尖接触、辅助骨、碰撞链、注册和资源引用。
7. 执行诗岸单 Editor Play Mode 检查；不进行联机、多 Editor 或独立游戏客户端验收。

已确认的转换结果：Blender FBX 往返验证通过，91,363 顶点、145,686 三角、285 骨、42 材质、170 顶点形态。最大权重误差 `2.98e-8`；顶点与形态坐标误差 `2.91e-7 m`；骨绑定位置误差 `4.15e-7 m`。Unity 导入为 96,458 顶点、145,664 三角、42 子网格、170 blendshape，Avatar `isValid && isHuman` 已通过。

最终验证记录见 `Docs/AI/ShianValidation.json`；菜单预览见 `Docs/AI/ShianPreview.png`。

- 武器手势库：68 条骨轨道、9,555 帧；最终近战库：70 条轨道、2,238 帧，来源标记为 `Quaternius-UAL1-UAL2-CC0-2026-10-24`。狙击手势按诗岸左右手实际尺寸校准，Unity 实测接触间距约 0.1803 mm。
- 编辑器检查通过 36 个 Humanoid 动作、273 组枪械姿态加 105 组连发采样、216 组近战采样、12 根辅助扭转骨、240 帧连续裙发运动及 600 帧静置。第一人称过滤后为 42,336 三角，完整身体为 145,664 三角。
- 原始待机回归在禁用全部脚本和 IK 后采样 0／1／4 秒的双腕：要求位于对应上臂外侧至少 5 mm，后偏不超过 35 mm。旧 Avatar 的 6 项检查全部失败，校准后全部通过；腕部相对上臂外移约 40–52 mm、前移约 16–34 mm。正面与侧面预览用于复核实际姿态。
- 独立 `ShianDemo` Play Mode 验证通过 831 帧：前进约 2.545 m，蹲／趴／踮脚／站立切换，下落气流和护裙响应，第一人称瞄准手势；菜单在 2→3→4→2→4 间切换及仓库头像生命周期正常。
- 头盔、护盾发生器与背包展示通过；头盔拟合参数为横向半径约 0.182 m、竖向尺寸约 0.338 m，长双尾没有纳入头部包围范围。
- 三角色选择按钮在 1280／1600／1920 宽度及普通／紧凑模式下共 18 项英文文字边界检查通过。窄列允许换行，保留完整角色名。

这些检查验证了现有角色系统的接入，没有启动客户端／服务端世界，没有进行联机验收或发布构建。碰撞采用骨链与胶囊／球代理，不是原 PMX 刚体关节模拟，也不能保证任意极端姿势完全不穿模。170 个顶点表情已保留，但不包含完整 MMD 材质／组形态行为。模型约 14.6 万三角、42 个材质槽，显著重于目前的初音资源；尚未制作 LOD 或完成目标设备性能分析。
