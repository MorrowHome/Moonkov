# 光环改装模块

从首页、顶部导航或仓库的 **光环改装** 直接进入改装台。仓库光环的右键菜单和双击入口也保留。左侧选择自己持有的步枪、紧凑步枪或霰弹光环，再选择供能、射击、辅助槽。三个槽对应底层的 Storage、Shaping、Utility，同槽互斥。

中央列出当前槽全部兼容模块，包括未持有的模块。选择只更新预览，不改库存。右侧显示用途、收益、代价和真实参数比较；确认安装或替换后才提交库存事务。伤害按每发所有弹丸全中计算，扇形阵列不会被误报为总伤害下降。供能与射击槽可以组合，预览保留其他槽和已有研究效果。

左侧用原光环预制体和正式模块 Sprite 预览外观。可切换改装前后，并播放充能或开火示例。示例只推进私有预览，不修改实际弹量。每个模块都显示一对左右镜像的实心几何饰件。供能位于 3／9 点，射击位于 1／11 点，辅助位于 5／7 点。原光环保留原色。供能饰件为暖黄，射击为青蓝，辅助为淡紫；图标使用相同配色，不叠加新圆环。

未持有的普通模块可直接前往对应补给商品；月核回流器进入月核研究或制造。获取后可以返回改装台。没有兼容光环时仍可预览步枪和霰弹模块，但不能安装。替换时原模块返回新模块所在位置，拆下时需要仓库空位。战局内可转移完整武器，但不能安装或拆下模块。

原六种模块均为独立 1×1 物品，可在补给商店购买，也能从补给箱搜刮。新增月核回流器同样为实体模块，但必须先研究再消耗回收材料制造，不进入普通购买或补给箱池。模块通过父子物品关系安装到具体光环上，部署、撤离、死亡掉落和跨玩家搜刮均保留模块身份。出售光环前必须先拆下模块。旧存档默认没有模块，无需删除或重建库存。

当前基础霰弹枪为 4 发、8 弹丸、5° 散射半角、每枚伤害 18、充能 2 秒、每发 12 能量。扩容后 6 发、2.7 秒；单独聚束为 3 发、2.25°；扇形为 12 弹丸、8°、每枚伤害 12，总伤害仍为 144。扩容加聚束为 5 发。快充加标记器每发耗电为 `ceil(ceil(12 × 1.5) × 1.25) = 23`。伤害基线以 [WeaponBalance.md](WeaponBalance.md) 和实际 WeaponRegistry 为准，本次界面改版不调整平衡。

月核回流器的步枪耗能为 3→2、霰弹为 12→8，充能均为 2→2.4 秒；与标记器组合时先计算 `ceil(E × 2/3)`，再计算 `ceil(E × 1.25)`，与既有生物研究和器官活动按原顺序组合。原建议 -25% 在 3 能耗步枪上取整后无收益，因此调整为减少三分之一。研究消耗已回收月核 1＋电路板 2；每件制造消耗已回收月核 1＋铜线圈 1。知识永久，实体模块死亡可掉落；入口和验证边界见 [月核成长](Planning/Missions/Mooncore-Progression-Status.md)。

模块改变之后保留已有的已充能弹量，缩容不会删除已付费弹药，扩容不会补弹。若缩容后暂时超过容量，可正常发射，降到容量以下后才可重新充能。新武器的初始弹量来自基础武器配置，不由扩容模块额外赠送。

三连发使用服务端与预测共用的状态逻辑：松开扳机后继续完成当前组；一直按住不会重复开启下一组，下一组需要再次扣扳机。失去瞄准、切枪、充能、空仓或死亡会取消剩余发射。组内沿用基础步枪发射间隔，组间间隔乘以当前健康操控倍率。

命中标记只在服务端实际造成伤害后产生，同一发霰弹只生成一个标记。当前合作战局的所有人类玩家共享标记，AI 不产生共享标记。标记显示固定的最后命中位置，每名射手的新命中替换旧标记；遮挡仍由场景深度决定，不跟踪目标，不透墙，也不由客户端预测确认。

```mermaid
flowchart LR
    Supply[商店 / 补给箱中的独立模块] --> Workshop[基地物品树安装 / 拆卸]
    Workshop --> Weapon[具体光环及三个互斥槽]
    Weapon --> Persistence[部署 / 掉落 / 搜刮 / 撤离保存]
    Weapon --> Mask[服务端装备模块标识]

    Prediction --> Projectile[每枚弹丸携带发射时模块标识]

```

实体模块共用一张白色透明图集和一个 `RifleHaloInk` 材质。每个可见光环最多显示三对 Sprite；保留原光环与瞄准中心留白，不添加体积边框或模块灯光。生物效果继续使用现有平面顶点色网格。`DollSinger.Runtime` 内的 `HaloModule` 仅定义无引擎依赖的模块标识，库存逻辑不反向耦合到表现程序集。

实体模块同槽互斥。饰件整张图形及其动画按左右镜像，随原主体边缘和缩放移动。每簇宽高按形状控制在原直径的 10% 至 16% 内，包含动作时的边缘控制在原局部半径的 1.30 倍内。矢量图源和生成说明位于 `ArtSource/HaloModules/`。预览复用相同的 `HaloModuleVisual`；静态画面只在选项或尺寸变化时渲染，纹理最长边不超过 512，离页后释放场景和纹理。原预制体引用保存在 `MenuCharacterSettings`，不复制武器资产。

编辑器入口：`Tools / Doll Singer / Check Halo Modules` 检查数值、总伤害、确定性散射、三连发及平面几何；`Preview Halo Modules` 用实际预制体生成 `Build/HaloModules/HaloModulePreview.png`；`Update Module Translations` 更新中英文字符串表，不重建字体。后端 `Backend/HaloWeaponChecks` 使用临时数据库验证模块安装、替换、持久化、部署、掉落、搜刮与出售边界。

改装台的原生布局和库存交互检查入口为 `Tools / Moonkov / Review Halo Workshop`。使用隔离示例库存和真实 WeaponRegistry，不读取或修改玩家档案。结果写入 `LocalData/HaloWorkshopReview/`。固定布局在 `Components/HaloWorkshop.uxml`，局部样式在 `HaloWorkshop.uss`，交互在 `ContainerInventoryView.Modules.cs`。

2026-10-25 改装台验证：Unity C# 编译、布局导入与 16 项定向检查通过。覆盖预览不改库存、安装不补弹、原位替换、拆卸、未持有模块、组合参数、扇形总伤害、只读、失败重试、忙碌防重复和无兼容光环状态。中文、英文原生布局和 420px 高正文已检查；实际截图尺寸见检查日志。终端 UXML 模板截图验证样式继承，没有代替真实账号与完整导航验收。

本次验证：Unity 脚本编译通过；编辑器模块数值、耗能叠加、总伤害、确定性散射、三连发生命周期和平面留白检查通过；真实预制体九格对比已渲染并目视检查。临时 PostgreSQL 数据库验证安装、替换、保存、部署、撤离、死亡掉落、跨玩家搜刮、战局拆装限制与出售保护通过，测试未修改玩家库存。实际第一人称遮挡、完整射击手感与双客户端标记同步尚未进行 Play Mode 验收。
