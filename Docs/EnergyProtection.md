# 能量护盾与生命维持项圈

## 2026-10-22：猫铃项圈

原头罩外观改为深蓝颈带、香槟金包边、淡紫折叠蝴蝶结和金色猫铃，背面保留供氧扣件。项圈位于原有高衣领上方、下颌下方的实际皮肤颈段；颈围不包括肩饰、衣服和头发。

`EnergyShieldPresentation.Collar.cs` 初始化时，从身体蒙皮中筛选颈骨／头骨权重占比至少 70% 的皮肤顶点，在颈部截面拟合内圈并留约 1.2 mm 间隙。拟合中心与方向存为真实 Neck 骨骼的局部姿态，`LateUpdate` 在角色动画之后更新，位置、俯仰、转头和侧倾共同随动。网格按原引用计数共享，截面拟合不在逐帧路径执行。

存档物品码 `energy_head_dome`／`helmet`、`Helmet` 装备槽和原储氧规则兼容；名称、描述、储氧提示、装备引导线和 UI Toolkit 图标改为项圈。头部球罩及其第一人称面罩移除，战斗护盾仍使用原独立装备。仓库人物复用正式表现，支持延迟创建、动画推进、装备和卸装。

Unity 编译、正式模型近景及整体搭配渲染通过。五个受控颈部姿态覆盖低头／抬头 35°、左右转头 55°、组合侧倾：位置误差最大约 0.00000051 m，旋转误差为零。卸装隐藏、仓库装备快照预览、中英文原生条目检查通过；十个本地化条目保留原 ID，没有重建字体。未启动对局、联机或独立构建，未覆盖全部衣物动态与动作。

以下为此前头罩与护盾的实现记录；头罩外观和面罩部分以上述项圈版本为准。

## 权威资源

- `energy_shield_generator` 使用独立 `Shield` 装备位。护盾、供能容量均为 100；停止受到战斗伤害 6 秒后，每秒恢复 8 点护盾，每恢复 1 点消耗 0.5 点供能。供能为零时不能免费恢复。
- 子弹、爆炸、近战和火焰先经过一次 `RaidHealth.CombatDamage` 护盾结算，剩余伤害再进入原有身体部位结算。中毒、出血与环境生理伤害沿用身体伤害路径。
- 每件装备保存自己的护盾、供能与氧气剩余量；移动、丢弃、死亡与结算前写回原物品。新物品的 `-1` 哨兵只初始化一次，零值是有效耗尽状态。电池补能沿用已有消耗品请求及物品版本校验。
- 两种模式都更新战斗护盾；Clash 仍暂停原有生存氧气与营养消耗。远征玩家沿用有限氧气系统，头罩密封状态传入该系统，不新增 NPC 氧气行为。
- `RaidHealth.Initialize` 的 `ProtectionInitialized` 守卫必须保留，避免复活或放逐流程重新赠送氧气。

## 客户端外观

`DollSingerNetworkPresentation` 在客户端模型上创建 `EnergyShieldPresentation`，从现有 Ghost 装备状态、命中点和事件序列读取表现数据。服务端不创建视觉组件；表现层不修改资源、库存、碰撞体或生命值。初次收到快照只记录序列，避免重播历史命中。

头部装备由原创程序生成的透明椭球能量罩、实体颈环和四个发光节点组成，约 0.4 秒从颈部向上展开。初始尺寸使用人形头骨及现有头发、头饰骨骼的上部范围估计，并随头部姿态移动。它不是完整服装，也不替换原角色网格。

当前拟合仅覆盖头部与上部发冠；低于颈部的长双马尾不在罩内。该方案尚未通过实际模型画面验收，脸部可读性、上部头发穿透、颈环位置及俯卧姿态都需要在后续单 Editor 检查中确认；不能将骨骼范围估计视为网格贴合验证。

独立护盾发生器显示在髋侧。身体战斗护盾仅在受击、破盾、恢复或正在充能时短暂显示波纹和碎裂，不维持常驻全身蓝球。射线枪与实体子弹把真实 `hit.point` 传入权威伤害接口；爆炸使用已有爆点接口。

第一人称拥有者的当前视角相机逐相机隐藏自己的头罩、颈环、发生器与身体护盾；受击只增加低强度画面边缘反馈，中心透明。第三人称及其他观察相机保留装备外观。相机结束及组件退出时恢复隐藏标记。

## 绘制与生命周期

- 表面使用专用 `MoonkovEnergyShield` Pass，通过当前相机真实剔除结果绘制。拥有者边缘反馈使用单独 Pass 标签，避免被常规透明绘制调用。
- 边缘反馈使用的 `Blit.Vert` 会读取 `_BlitScaleBias`；该绘制明确提供单位缩放和零偏移，避免沿用前一个后处理 Pass 的全局 UV 状态而把边缘反馈移入画面中央。
- 绘制顺序为 601，位于现有 SilverPrint 与 Dark Sight 之后；不修改全局调色、Renderer 资产或其他视觉系统。
- 表面读取本相机已声明的深度并显式裁剪遮挡，无有效深度时不画表面；折射读取独立 RenderGraph 色彩副本，不同时读写同一附件。
- 不新建相机、World、碰撞体或持久 RenderTexture。网格按引用计数共享；材质和合成音频由组件私有持有，退出时释放。无可见表面且无第一人称反馈时不排入绘制。
- 硬件复用已有 `TacticalMetal` / `TacticalIndicator` 材质资源，通过属性块着色，不修改原资源。音效为代码生成的短音，经现有 SFX 混音组播放。没有引入外部模型、贴图或音频。

## 近战接入约定

`BountyClashDamage.Apply(..., RaidDamageKind.Melee, (float3)contact.Point)` 的最后一个可选参数为世界空间命中点，两个 Apply 重载均提供。请在既有近战命中路径传入实际接触点，并保留原有自伤、队伍、归属、次数和命中标志逻辑。本次没有修改 `ServerMeleeSystem`。

## 当前验证边界

视觉制作组只进行了源码静态核对：接入路径、参数传递、声明与括号、材质 Pass 标签、深度依赖、相机可见性恢复、资源释放及受保护字体哈希。协调方随后使用现有 Bee response files 和 Unity 自带 Roslyn，在隔离输出目录串行编译了 `DollSinger.Runtime` 与包含三个新表现文件的 `Assembly-CSharp`，均为退出码 0；主程序集仅有两条原有过时 API 警告。证据位于 `Library/BuildValidation/SourceOnly-20261022/`。此过程没有启动 Unity、Play、Blender 或游戏，也没有覆盖现有 Bee/ScriptAssemblies DLL。

该编译不执行 Unity 导入、IL 后处理、Shader 编译或实际渲染。新增 Shader、外观与完整装备行为仍未验收，不能从 C# 编译通过推断视觉质量或发布就绪。
