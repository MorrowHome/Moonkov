# 局内文字聊天

2026-10-26。

## 玩家操作

- Enter 打开聊天。再次按 Enter 发送并收起。空消息不发送。
- Esc 取消输入并保留草稿。中文选词期间，Enter 和 Esc 先交给输入法。
- 点击输入框旁的频道按钮，在队伍和全局之间切换。新战局默认队伍。未组队时不能发队聊，可手动切到全局。
- 展开时可查看最近 100 条。收起时显示最近 5 条。没有新消息 10 秒后淡出。
- 阵亡、撤离和结算后，只要仍连接当前战局，就能继续聊天。阵亡消息带有标记。
- 单人战役和单人赏金隐藏聊天。没有语音、私聊、大厅聊天或聊天存档。

## 接入方式

- `RaidHUD.Chat.cs` 负责 HUD 生命周期、发送和输入拦截。`RaidChatView` 使用原生 UXML／USS 和现有中英文本地化。
- `RaidChatServerSystem` 从 RPC 的真实连接查找已加入玩家。在线远征读取服务端档案中的队伍与实例。赏金读取当前比赛队伍。普通合作 LAN／直连把已加入玩家视为同队。
- 队聊只发给发送时同队的连接，包括发送者。全局发给当前战局内已加入的玩家。机器人和正在断开的连接不参与。
- 客户端只提交会话、请求编号、频道和正文。名字、阵亡标记与队伍由服务端决定。消息正文和昵称不解析富文本。
- 正文最多 120 个 Unicode 码点，使用 `FixedString512Bytes`。输入两端均验证。控制字符和换行会被清除。每人可连续发 3 条，此后每秒恢复 1 条额度。
- 消息只在服务端确认后出现。失败或 5 秒未确认时保留草稿，不自动重发。请求、消息和会话公告分别防重或排序。较旧的会话公告不能恢复上一场记录。
- 聊天记录由客户端 World 持有。断线、World 销毁或新赏金比赛会清空。重连不补发历史。
- 新增三类 NetCode RPC。客户端与服务器必须一起更新。没有修改后端接口、数据库或存档格式。

## 维护约束

- `ChatInputBlocked` 同时进入既有 `PointerRequested` 和游戏动作拦截。打开当帧、关闭当帧及下一帧都有保护。不要只在 HUD 的 LateUpdate 中禁用输入。
- `ClientInputSenderSystem` 还会清除当前 tick 与待发送缓冲中的旧射击。只清读取端会留下上一帧的按键。
- 聊天优先消费 Esc。背包、地图、任务日志、手雷和定时操作的独立快捷键也要检查聊天拦截。
- 从 `CloneTree()` 返回的模板中取出内层根节点时，显式挂上聊天 USS。否则会丢失模板容器上的样式作用域。
- 运行时每帧只检查状态。列表只在消息、频道、可用性或语言变化时刷新。消息和可见行都有上限。

## 验证

- Unity 6000.5.10f1 编译通过。最终检查时 Console 错误和警告均为 0。
- `RaidChatChecks.Run()` 通过 48 项检查。使用隔离 ECS World，覆盖真实接收连接、在线和赏金队伍、合作直连、换队、未组队、阵亡、撤离、断线、单人隐藏、旧会话、请求防重、发送限流、文本边界及伪造来源。
- `RaidChatReview.CheckEditing()` 检查取消保留草稿、空消息和确认发送。`CheckInputIsolation()` 调用真实输入读取及发送系统，检查移动、射击、当前 tick 和下一 tick 缓冲，并测试 IME 组合与提交当帧不会发送。
- `Tools/Moonkov/Review Raid Chat` 可打开原生样例。已查看中文、长昵称、阵亡标记、纯文本标签与 HUD 的位置关系。记录的实际原生 panel 为 1280×682。窗口受到桌面可用区域限制，不能将其称为 1280×720 或 1920×1080 验收。
- 本地结果在忽略目录 `LocalData/RaidChatReview`。样例界面和隔离检查不代表真实战局已验收。
- 未进入 Play、未做双端联机、完整 Player 构建、目标双分辨率或系统中文输入法实际选词验收。IME 回调测试不能替代系统输入法测试。
